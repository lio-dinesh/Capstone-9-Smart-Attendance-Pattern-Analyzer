# Data Dictionary: Smart Attendance Pattern Analyzer

**Document Version:** 1.0.0  
**Project:** Smart Attendance Pattern Analyzer  
**Standard:** Open Academic Analytics Data Specification  

---

## 1. Overview
This data dictionary details the schema, data types, nullability, constraints, allowed enum values, and analytical roles for both input datasets and generated reconciliation fields within the Smart Attendance Pattern Analyzer platform.

The system uses a **reconciliation-first paradigm** where student attendance logs (`attendance_records.csv`) are validated against an expected timetable schedule (`expected_sessions.csv`).

---

## 2. Expected Student Sessions Dataset (`expected_sessions.csv`)

Represents the official timetable schedule indicating which students were expected to attend specific course sessions.

| Column Name | Data Type | Nullable | Primary / Foreign Key | Description & Constraints | Example Value |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `student_key` | String (VARCHAR 50) | No | PK (Composite) | Pseudonymous opaque fictional student key. Format: `STU-XXXX`. | `STU-0012` |
| `session_id` | String (VARCHAR 100) | No | PK (Composite) | Unique session identifier encoding course, section, term week, and slot. | `SES-CS101-SEC-A-W01-1` |
| `session_date` | Date (ISO 8601) | No | Indexed | The calendar date of the scheduled session. Format: `YYYY-MM-DD`. Validated to ensure realistic academic calendar dates. | `2026-09-07` |
| `course_code` | String (VARCHAR 50) | No | Indexed | Departmental course identifier. Allowed values: `CS101`, `MATH201`, `ENG102`, `DS301`. | `CS101` |
| `section` | String (VARCHAR 50) | No | Indexed | Cohort section code. Allowed values: `SEC-A`, `SEC-B`. | `SEC-A` |
| `timetable_slot` | String (VARCHAR 50) | No | None | Scheduled time band. Allowed formats: `08:30-10:00`, `10:15-11:45`, `13:00-14:30`, `15:00-16:30`. | `08:30-10:00` |
| `session_held` | Integer / Boolean | No | None | Binary indicator: `1` (session held as scheduled), `0` (session cancelled due to holiday, campus event, or instructor absence). Cancelled sessions are strictly excluded from attendance rate denominators. | `1` |

## 3. Recorded Attendance Dataset (`attendance_records.csv`)

Represents logs recorded by faculty members or automated classroom check-in systems.

| Column Name | Data Type | Nullable | Primary / Foreign Key | Description & Constraints | Example Value |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `student_key` | String (VARCHAR 50) | No | FK references expected | Opaque student key corresponding to expected roster. | `STU-0012` |
| `session_id` | String (VARCHAR 100) | No | FK references expected | Unique session identifier corresponding to expected timetable. | `SES-CS101-SEC-A-W01-1` |
| `status` | Enum (String) | No | Indexed | Attendance status recorded by instructor. Allowed values: `PRESENT`, `LATE`, `ABSENT`, `EXCUSED`. | `PRESENT` |
| `recorded_at` | String (ISO 8601) | Yes | None | Timestamp of when the check-in occurred. Optional for absences. Example: `YYYY-MM-DDTHH:MM:SS`. | `2026-09-07T08:35:12` |

## 4. Derived & Reconciled Attributes

Generated by the analytical engine during reconciliation between scheduled sessions and recorded logs.

| Attribute Name | Data Type | Possible Values | Analytical Definition & System Handling |
| :--- | :--- | :--- | :--- |
| `status` (Reconciled) | Enum | `PRESENT`, `LATE`, `ABSENT`, `EXCUSED`, `MISSING` | If a student was expected at a held session (`session_held == 1`) but no recorded log exists, the engine assigns `MISSING`. `MISSING` entries are tracked in data quality audits and excluded from attendance denominators. |
| `is_missing` | Boolean | `true`, `false` | Quick query boolean indicating whether the record was absent from instructor submissions. |
| `reconciliation_status` | String | `Recorded: PRESENT`, `Recorded: LATE`, `Recorded: ABSENT`, `Recorded: EXCUSED`, `Missing Entry`, `Session Cancelled` | Human-readable audit status displayed in Data Explorer. |
| `completeness_rate` | Float (0.0 to 100.0) | Continuous percentage | Ratio of valid recorded expected entries to total expected sessions held. Figures below 85.0% flag the cohort as *Provisional*. |

## 5. Review Flag Entity (`review_flags`)

Persisted table storing explainable anomaly detection alerts and human review records.

| Column Name | Data Type | Nullable | Description |
| :--- | :--- | :--- | :--- |
| `id` | Integer (PK) | No | Internal autoincrement primary key. |
| `flag_key` | String (Unique) | No | Unique business key e.g., `FLAG-STREAK-STU-0012` or `FLAG-DATA-MISSING-DS301-SEC-B`. |
| `category` | Enum (String) | No | `Attendance Pattern` or `Data Quality`. |
| `rule_name` | String | No | Human-readable rule title (e.g., `Consecutive Absence Threshold`). |
| `target_id` | String | No | Identifies the student (`STU-XXXX`) or course section affected. |
| `period` | String | No | Date range during which the anomaly occurred. |
| `evidence` | Text | No | Human-readable audit findings and exact supporting figures. |
| `threshold_description` | String | No | Configured rule threshold that triggered the prompt. |
| `suggested_action` | String | No | Contextual recommendation for educator or mentor follow-up. |
| `status` | Enum (String) | No | Current review workflow state: `Needs context`, `Data issue`, or `Reviewed`. |
| `reviewer_note` | Text | Yes | Optional qualitative note recorded by the academic advisor or faculty reviewer. |
| `created_at` | DateTime | No | System timestamp when the flag was first generated. |
| `updated_at` | DateTime | No | Timestamp of the most recent status or note amendment. |
